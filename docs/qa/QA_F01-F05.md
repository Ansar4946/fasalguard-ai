### Harness caveats (so the results are read correctly)

1. Git Bash converted `-e MEDIA_LOCAL_DIR=/data/media` into a Windows path on the first start; uploads returned 500 until I recreated the containers with `MSYS_NO_PATHCONV=1`. All results below come from the corrected stack. This was my error, not an application defect.
2. I ran `redis-cli flushall` a few times between test groups. The BullMQ worker once left a satellite job unconsumed for more than 200 s until I restarted it (F02-20 note); I believe my flush removed BullMQ marker keys, so I do **not** report it as an application defect. Restart-recovery behaviour was tested separately (F01-28, F01-29, F01-29b) and passes.
3. The login throttle is 5 per minute per client, so the AUTH script sleeps 65 s between groups. `auth.integration-spec.ts` ("lists, revokes one, and revokes all device sessions") fails with 429 for the same reason (test design, see D17).
4. The first run of the F05 cross-service integration test failed because the core API container pointed at a different database than the test fixtures. It passes against a core API on `f03_test` (shown below). Not an application defect.
5. Anonymous Docker volumes created by the Postgres/Redis images were deleted after the run.
