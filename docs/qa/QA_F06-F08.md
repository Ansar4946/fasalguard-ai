## Environment notes and caveats (read first)

- The default `services/api` Docker build fails (D4). The qa2 API image was built with `docs/qa/qa2/qa2-api.Dockerfile`, identical to the product Dockerfile except `npx tsc -p tsconfig.build.json` (which still emits JS) replaces `npm run build`.
- The web image runs `NODE_ENV=production`, which by design rejects non-HTTPS mutation origins (`lib/auth/origin-policy.ts`, 403 "Cross-origin request rejected"). For the HTTP-only isolated stack the web container was run with `NODE_ENV=development` (documented in `qa2-compose.yml`). Production origin behaviour was therefore not exercised.
- Real provider data used: AssemblyAI (key from `.env`, never printed) for speech-to-text; live public AMIS (www.amis.pk) was reached. At 03:54 PKT the live AMIS page for 2026-10-16 contained no price rows (0 records parsed), so the market database was populated by replaying the 5 genuine AMIS HTML pages captured on 2026-10-14 (`docs/features/f07-results/amis-*.html`) through the real provider parser and worker. These rows are genuine AMIS data dated 2026-10-14, not live. No data was invented.
- All speech audio is synthetic English from the Windows SAPI voice (not farmer speech). No Urdu or Hindi audio exists.
- Throttle-aware design: transcription is limited to 10 per minute, so the API script paces itself (sleeps 62 s between groups) so each case tests what it says.
- Caveat to disclose: before I set `REDIS_URL`, two Jest integration runs (`voice-assistant`, `media`) used the default `127.0.0.1:6379`, which is the shared `fasalguard-platform-redis`. They only connected; I did not inspect whether BullMQ workers in the Nest test app touched shared queues during those ~1 minute windows. All later runs used qa2 Redis. Also a stray debug file `D:\Fasal Guard Development Workspace\dbg7.cjs` (outside the repo) could not be deleted by me because the safety check blocked the removal; please delete it.

## How to reproduce

1. `docker compose --env-file <env with QA2_JWT, QA2_PG, ASSEMBLYAI_API_KEY> -f docs/qa/qa2/qa2-compose.yml up -d --build`. The compose references the QA Dockerfile by an absolute path; if postgres is slow to initialise, rerun `up -d` so migrate retries.
2. `sh docs/qa/qa2/run.sh <scratch dir holding qa2.env, speech-en.wav, silence.wav> node docs/qa/qa2/<script>`. Scripts: `f08-api.cjs`, `f08-browser.cjs`, `f07-browser.cjs` (`PHASE=empty|full`), `f07-outage.cjs`, `f07-sync.cjs` (run inside qa2-api with `MODE=`), `f06-mobile-explore.test.mjs`, `test_f06_platform_explore.py`.
3. `docker compose ... down -v` and `docker rmi qa2-api qa2-web`.
