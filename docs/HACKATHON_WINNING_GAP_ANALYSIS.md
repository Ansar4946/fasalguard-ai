# Hackathon Winning Gap Analysis

**Date:** 2026-08-18
**Scope:** Audit only — no implementation performed. This document maps the existing FasalGuard AI codebase against the target pipeline (Register → Create Farm → Select Crop → Gemini Crop Roadmap → Monitored → Gemini Farm Intelligence → Risk Detected → Action Generated → Notified → Farmer Acts → Follow-up Verifies → Usage Measured → Subscription/Revenue) and against the three judging axes: Business Viability, AI-Native Operations, Category Impact.

Findings are based on direct code inspection (file:line evidence) by three parallel research passes covering (1) monetization/growth infrastructure, (2) Gemini/AI telemetry + Google Cloud, (3) core farm workflow/analytics/notifications. Every "EXISTS" claim below was verified by reading the actual implementation, not by trusting existing docs or comments. Existing self-audit docs (`docs/BUSINESS_EVIDENCE.md`, `docs/API_PRODUCTION_CHECKLIST.md`, `docs/PRODUCTION_BLOCKERS.md`, `docs/MOCK_DATA_AUDIT.md`, `docs/FEATURE_SCORING_FRAMEWORK.md`) were cross-checked against code and found accurate everywhere they were re-verified — this document supersedes none of them, it consolidates and extends them for the hackathon framing.

---

## 0. Executive summary

FasalGuard AI has a genuinely strong, non-trivial backend: real transactional auth, real PostGIS farm/field modeling, a real Gemini-powered autonomous investigation pipeline (**Farm Brain**, confirmed live end-to-end this session with real token counts and latency), a real deterministic risk-scoring engine, real geospatial outbreak clustering, real satellite NDVI analysis, and a carefully-designed, honestly-scoped business-evidence schema with real SQL analytics endpoints that refuse to fabricate numbers.

What's missing is almost entirely **connective tissue and monetization**, not core engineering:

- **No functioning subscription/payment system.** Tables exist (`subscriptions`, `subscription_payments`) but nothing writes to them — no controller, no payment provider, no webhook.
- **No testimonial/feedback collection UI**, despite a schema (`user_feedback`, with a `consent_to_quote` field) built specifically for it.
- **The automatic monitoring loop is a dead end.** Satellite/weather crons compute a risk score but never escalate to Farm Brain, a task, or a notification — only the on-demand, farmer-triggered Farm Brain path (with explicit confirm-to-execute) reaches the farmer.
- **No outcome/follow-up verification is ever written** (`farm_verifications`, `farm_interventions` are read-only schema stubs — zero INSERTs anywhere in the codebase).
- **Crop selection is broken in the UI**: the onboarding form collects a crop type but never sends it to the backend, so `crop_cycles` is effectively always empty for real users — which silently breaks weather alerts, risk scoring, and outbreak matching for every real farmer, since those queries filter on an active crop cycle.
- **⚠️ Integrity risk for judging**: `app/(government)/government/impact/page.tsx` (the one system-wide, non-farmer-scoped "impact" dashboard that exists) renders **100% hardcoded mock numbers** (e.g., "143,890 registered farmers," "2,812 farmers warned") from a static file, explicitly commented in-code as "Demo platform accounts" / "Illustrative trend." It is completely disconnected from the real, working `/analytics/impact` and `/analytics/viability` endpoints. If shown to judges without modification, this would violate the "no fabricated numbers" rule this project has otherwise followed carefully. **This needs to be fixed or hidden before any demo — flagging as the single highest-priority integrity risk found.**
- The chatbot/"assistant" surface is **not** Gemini — it runs on Alibaba Qwen, and defaults to a hardcoded fake stub unless explicitly configured. Any judge-facing claim of "Gemini-powered assistant" would be false; only Farm Brain is genuinely Gemini.
- The self-hosted crop-scan vision backend referenced by the default config **has no matching route** in the Python service that's supposed to serve it — a crop-scan run in the default stack would 404, not silently fake a diagnosis, but it also wouldn't work.

## 3. Cross-cutting findings worth acting on first

1. **The `government/impact` mock dashboard is the single highest-priority item to address before any judge demo** — not because it's hard to fix, but because presenting it unmodified would contradict this project's own anti-fabrication rules. The real, working analytics endpoints it should be calling already exist.
2. **Fixing crop selection in `farm-setup.tsx` (item 1) has outsized leverage.** Several already-correct backend systems (weather alerts, risk scoring, outbreak crop-matching) silently degrade or no-op for every real farmer today purely because `crop_cycles` is never populated — this is a one-field wiring fix, not new engineering, and it would make three existing systems start working correctly for real users.
3. **Don't claim the assistant/chatbot is Gemini-powered.** It's Qwen, and defaults to a canned fake response unless explicitly configured — a judge asking "what powers your chatbot" deserves an accurate answer, and conflating it with Farm Brain's real Gemini integration would be a fabrication risk.
4. **The automatic-monitoring → Farm Brain gap (item 8) is the biggest structural blocker to the target pipeline as literally specified.** Today "Risk Detected → Action Generated" only happens if a farmer manually opens the app and starts an investigation, then manually confirms each proposed action. Closing this loop (auto-trigger Farm Brain when a risk-score crosses a threshold, or at minimum surface a notification prompting the farmer to investigate) is the most direct way to make the pipeline actually autonomous end-to-end.
