## Farmer stories and acceptance criteria

1. As the owner, import 1–25 named WGS84 Polygon features into my farm, including interior holes, and see authoritative acreage. Imported identities, owner IDs and claimed area cannot override server data. The complete import commits once or rolls back; retrying the same key does not duplicate fields.
2. Select an existing field, validate its shape, edit its exterior and save. Reload retains geometry, area and version. Holes remain excluded in farm, field and satellite maps. A concurrent write returns 409 rather than overwriting another save.
3. Download my saved fields as a private GeoJSON FeatureCollection. Foreign users, revoked sessions and deleted resources cannot reveal geometry.
4. Capture individual GPS corners, inspect reported accuracy, explicitly add each corner, and confirm before saving. Persist source, measurements and timestamps. A permission failure adds no corner; GPS and calculated area are never described as a cadastral survey.
5. Invalid coordinates, malformed rings, self-intersections, invalid/outside holes, outside-farm fields and boundaries crossing a farm hole fail without partial writes. Outages retain editable UI input and provide errors. Empty inventory is explicit.

Limits: requests ≤262144 bytes; UI file ≤250000 bytes allowing envelope overhead; ≤25 imported features and ≤5000 total positions; ≤20 holes per Polygon; only 2D longitude/latitude, finite WGS84 coordinates, closed rings with ≥3 distinct vertices; no alternate CRS/MultiPolygon/dateline-crossing edges. GPS requires positive finite reported accuracy ≤10000m, timezone-aware timestamps and samples matching every exterior corner. Accuracy is retained as reported, never improved or authenticated by the server.

## Scientific accuracy, security and privacy

PostGIS `ST_IsValid` checks topology before FastAPI geography measurement; `ST_CoveredBy` includes parent holes. `ST_Area(geography,true)` uses the WGS84 spheroid in square metres, hectares divide by 10000 and international acres divide by 4046.8564224. Independent executed pyproj 3.7.2 `Geod(ellps='WGS84').polygon_area_perimeter([0,1,1,0,0],[0,0,1,1,0])` gave 12308778361.469452 m²; the real PostGIS integration test checks that reference at relative tolerance 1e-10 and verifies hole subtraction. Area accuracy does not establish accuracy of a farmer's drawn/GPS boundary.

Primary references: [PostGIS ST_Area](https://postgis.net/docs/ST_Area.html), [ST_IsValid](https://postgis.net/docs/ST_IsValid.html), [GeoJSON RFC7946](https://www.rfc-editor.org/info/rfc7946/). Input winding is tolerated; holes are treated topologically. Legacy coordinate winding is retained; no claim of cadastral certification is made. Centroid is a planar display summary and may lie outside a concave field, not a verified sensor position.

Owner checks use live shared users, farms and sessions. Imported area/identity properties are discarded. Transactional retries are scoped to the owner and recheck current access; deleted imported fields cannot be revealed through replay. Logs include request/resource IDs, counts and source, not full GPS coordinates or bearer tokens. Exports carry `private, no-store` and nosniff; no public links. Farmer boundary/GPS data is sensitive; operators must apply the existing access, backup, retention/deletion and audit policies to the new metadata/ledger. Ledger stores the import response (including original geometry) until database retention/deletion policy removes it; no automatic retention job is introduced.

GPS and random UUID generation require HTTPS in production (localhost is permitted for development). Browser tests use an isolated loopback TCP proxy to preserve secure-context browser behavior, not a production TLS workaround. Permissions denial, service outage and tile outage are explicitly tested separately from live hardware/provider availability. No background location tracking occurs.
