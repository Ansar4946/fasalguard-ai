## Contracts and data flow

All routes require a live shared JWT session and FARMER role. Field lookup requires ownership
through farm/farmer and excludes deleted farms/fields. Non-owner returns 404.

| GET `/api/v1/fields/{uuid}/weather/...` | Response |
|---|---|
| `forecast` | `fieldId`, provider, timezone, fetchedAt, generatedAt compatibility alias, nullable providerIssuedAt, expiresAt, ageSeconds, freshness, resolutionMinutes, current, hourly, daily, rawMetadata, cachePolicy |
| `current` | Same provenance, `observedAt` compatibility field and `weather` point; this is model current weather, not an on-field observation |
| `risks` / `suitability` | Crop, assessment, productionAssessment, rule matches/version/source/valid times, approval flags, recommendationAllowed, disclaimer and freshness |

Temperature °C, rain/ET0 mm, wind km/h, humidity/probability %, radiation W/m², soil water m³/m³.
Daily rain is native provider daily aggregation; hourly rain/ET0 represent interval quantities.
Soil water is shallow model output, not measured root-zone moisture. Unknown values remain null.
Open-Meteo current response omits some hourly variables; these remain unavailable in the current card.

Web → existing BFF → existing FastAPI → ownership lookup → per-field forecast PostgreSQL/Redis
cache → bounded live provider request → validated bundle → shared forecast table → UI.
Cache sharing uses rounded field-centroid coordinates (3 decimals); provider grid coordinates
remain metadata. A shared-cell cache hit still writes a forecast for each requesting field.
Forecast metadata includes the full validated bundle and cache location key. Existing historical
rows with empty metadata do not qualify for fallback. Moving a centroid invalidates its old cache.

`fetchedAt` is retrieval time. Provider issuance time is unknown and stays null. `generatedAt`
is retained only as a compatibility alias, not claimed as model issuance time. ISO timestamps
include UTC offsets; daily grouping/display uses Asia/Karachi, independent of browser timezone.

## Availability and operations

Two provider attempts maximum, bounded socket timeouts and streaming response cap 1 MB.
Untrusted Retry-After cannot cause an unbounded sleep. Provider errors use sanitized codes;
the API never returns the upstream URL/key. No alternate provider is silently substituted.
PostgreSQL transaction advisory locks prevent concurrent provider fetches, including when Redis
is down. Cold callers wait up to seven seconds for a refresh, then receive a retryable 503.
Redis socket/connect timeouts are 0.3 seconds; PostgreSQL remains the fallback cache.

Fresh TTL defaults to 900 seconds. After expiry a failed/ongoing refresh can return the same
stored forecast up to `TTL + WEATHER_MAX_STALE_SECONDS` age (default extra 3600 seconds),
marked STALE with original fetchedAt/expiry. Beyond that, 503. Failed refresh never advances
retrieval time. Actionable crop warnings require fresh data and expert-approved rules.
The browser invalidates eligible guidance at expiry, revalidates, and refreshes on focus.

No new Celery schedule is needed for this on-demand vertical slice. Existing weather alert
schedule/consent/dedup remains owned by Nest; F04 does not start a duplicate email scheduler.
Automated forecast prefetch and transactional email delivery improvements are later work.

## Security, privacy, science and blockers

No secrets copied into source or evidence. Test JWTs remain in private `/tmp` files, not tracked.
Exact field ownership is verified before cache access. No farmer/user identifiers enter the
shared provider cache; persisted field records remain scoped by access checks. Forecasts are
regional numerical model estimates sampled near a centroid, not field sensors, disease
predictions, yields, or guaranteed local conditions. No fabricated crop thresholds are seeded.
Expert-approved rules require review for crop, units, locality and growth-stage applicability;
single-hour matches do not establish sustained exposure or a validated disease prediction.

BLOCKED_EXTERNAL: commercial customer endpoint authentication/subscription verification and
real agronomic expert rule approval/local validation. Live email delivery, production deployment,
backup/restore, production load and disaster recovery are not certified by this feature test.
No model file or inference claim is involved: weather is obtained from the external provider.

The hero's current precipitation condition and daily rain probability describe different periods;
the reviewer suggests a future wording refinement to label the latter explicitly as today's chance.
