## Stories and acceptance criteria

1. Capture a crop photo against my cached owned Field/CropSeason; retain it and history across process restart with no network. Persist photo, capture ID/hash/time and model provenance, or explicitly state no prediction was generated.
2. With an approved, licensed classifier installed, run inference in airplane mode from real image pixels. Verify model hash, native loading, tensor contract, crop compatibility and finite outputs. The same image under a different filename must not change the result; appropriate distinct reference images must produce image-dependent scores without requiring every pair to change class.
3. Keep unsupported, corrupt, missing or incompatible models/photos explicit. Never use random labels, an implicit cloud fallback or a substitute crop model. Display screening uncertainty; scores are not validated disease probabilities.
4. Synchronize unchanged capture IDs safely after reconnecting. Retries/concurrent deliveries create one observation; changed payloads conflict. Atomic local acknowledgements and pull cursors prevent lost pending records. Reauthentication/outages preserve local records.
5. Keep account histories isolated, protect retained files and keys, reject foreign/deleted field/season access and revoked sessions, and never promote client-supplied predictions to verified diagnoses.

Acceptance2 and full native acceptance1/3/5 remain blocked. Unit tests and an ONNX code path are not actual model execution evidence.

## Database, API and data flow

Unified identities are retained: User → Farmer/farmer_profiles → Farm → Field → CropSeason/crop_cycles. The capture binds explicit fieldId and cropSeasonId, never whichever season is active when a job later runs.

Migration41 adds offline_crop_observations: serverUUID, owner FK, clientUUID, unique scan FK, crop-cycle FK, canonical request hash, immutable JSON capture payload and created timestamp. Unique(owner_id,client_id). A new capture creates an existing crop_scans row in CREATED state and stores offline evidence separately. It does not create diagnoses or model_predictions, and does not alter a verified scan. Existing model_versions metadata holds approved ONNX manifests; no model rows are seeded.

| Endpoint, prefix `/api/v1` | Contract |
| --- | --- |
| GET `/offline-scans/context` | authenticated ownerId and up to500 owned field/season choices |
| GET `/offline-models/manifest` | reviewed ONNX_MOBILE releases from model_versions, or available=false/NO_APPROVED_OFFLINE_MODEL |
| POST `/offline-scans/sync` | `{captures:[{clientId,fieldId,cropSeasonId,capturedAt,imageSha256,prediction:null or {modelVersionId,modelSha256,label,score}}]}` → results with clientId/id/scanId/SYNCED, clientInferenceVerified=false |
| GET `/offline-scans/changes?cursor=...` | owner-scoped offline events, string bigint cursor, at most100 events, hasMore |

Flow: optional authenticated cached context → local capture/re-encode → optional installed-model native inference → encrypted file plus SQLite capture/outbox → HTTPS FastAPI/shared JWT/session check → ownership/season validation → perowner advisory transaction lock → immutable request hash/deduplication → existing crop_scan plus offline observation and sync event → validated local ACK. Pull applies one page and cursor in a single local transaction; differing existing payloads roll back the page and retain the cursor/local record. Images remain encrypted on the original device; synchronization is metadata/evidence only, not photo upload/download.

Limits:20 captures per batch,64KiB streaming body cap,100 new captures/hour/owner,8s database statement timeout,5s owner-lock timeout,15s client HTTP deadlines,10MiB/20MP selected photo cap and320px minimum edge,100MiB model cap,32–512px fixed NCHW inputs and up to200 classes. Capture timestamps require timezone and permit at most5minutes future clock skew. Server errors include400,401,403,404,409,413,429 and503; storage failures are sanitized. Foreign/incompatible context is404; changed ID payload or unapproved model is409. A replay rechecks current field/season access before returning its receipt.

Manifest approval contract: existing model_versions provider ONNX_MOBILE, operator-reviewed metadata.approvalStatus=APPROVED and metadata.manifest validated by schemas.Manifest. Include exact cropId, artifact SHA256, license, evaluationReference, labels, input size, NCHW/stretch/RGB normalization and logits/probability interpretation. Existing row ID/model/version are authoritative. Release reviewed bundled assets through an app release; runtime arbitrary URL model downloads are not supported. Model/dataset rights, actual native inference/parity and field evaluation must be verified before any approval. Hashes establish integrity, not model accuracy or publisher authenticity by themselves.

## Security, privacy and scientific limitations

Important discovered blocker: current `services/api/src/domain/auth/dto/auth.dto.ts` LoginDto and `auth.service.ts:login` still issue sessions from identifier/device without checking a password or OTP. This behavior was inspected directly; no credentials were exercised or logged. No F06 mobile login was connected to it. OFFLINE_SYNC_ENABLED remainsfalse by default, and production Settings explicitly refuses enabling it. Existing insecure login is not repaired by this F06 foundation and remains a project production blocker.

Retained photos use AES256-GCM through @noble/ciphers2.4.0, separate owner keys in SecureStore, fresh12-byte Expo CSPRNG nonces, versioned envelope and owner/capture AAD; keys/plaintext byte buffers are cleared after use where possible. Photo originals remain the user's camera/gallery files; normalized temporary JPEGs are removed after capture. SQLite requires an actual SQLCipher cipher_version or opening fails closed. Device key storage, native encryption, crash/temp cleanup, iOS protection/backup behavior and physical device/account security are not runtime verified. Encryption does not establish those device properties automatically. No server/provider secrets appear in EXPO_PUBLIC variables.

Client predictions are untrusted observations, even if their claimed model is approved; the server cannot prove that a modified client ran it. isFirmDiagnosis is never asserted and verified diagnoses are not overwritten. A confidence/model score is not a calibrated disease probability. No crop support or field accuracy is inferred from PlantVillage benchmarks; reference assets do not cover wheat/rice/cotton. Missing/out-of-scope models yield no result, and no treatment prescription is generated.

Current history shows100 latest metadata rows; no photo viewer or native rescreen-from-encrypted-history flow. Context snapshots are capped500 entries and lack pagination/refresh UI. Session refresh/secure sign-in integration is blocked; expired credentials preserve pending work. No automatic adoption of another account's history. No retention/deletion UI, orphan-file reclamation, biometric gate or cross-device photo recovery is claimed. Production retention/key-recovery/accessibility/Urdu UX/device performance and inference cancellation/timeout behavior need further work.
